# Исходные утилиты записи — не часть пользовательского CLI

Это точные авторские утилиты захвата/рендеринга v5. Запись уже сделана; просмотр
MP4/кадров не исполняет команды и не вызывает модели. Нормальный запуск проекта
описан в корневом README. Эти утилиты не нужны для продолжения кейса.

При отдельном воспроизведении на новом разрешённом **учебном** root:

1. Установить проект в его отдельную `.venv-dev` по README; восстановить backup
   с явным доверенным digest. Не наследовать доступы, права, бюджет и credentials.
2. Скопировать утилиты из этой папки в `<project>/submission/` с теми же именами:
   в исходниках ROOT определяется относительно этой позиции. Использовать новую
   выходную папку, не перезаписывать архивы, captures и существующий кейс.
3. `record-terminal.py` требует авторский JSON plan и доступную PTY; plan должен
   содержать настоящий root/case и явный список собственных разрешённых команд.
   В v5 он запускал `review-demo-v5.py` без новых модельных задач. `pause` создаёт
   настоящий новый checkpoint. Старую запись воспроизводить как live output нельзя.
4. Рендеринг использует локальные macOS AppKit/Swift, pinned Arial для PDF и
   FFmpeg. PNG зависит от ОС/шрифтов; другая ОС этим не принята. Не устанавливать
   эти компоненты без отдельного разрешения. `render-v4-pdf.swift` поддерживает
   аргумент `v5`; это общий движок, а не подмена версии документа.
5. `build-review-media-v5.py` дополнительно требует `submission/v5-content/`
   с исходными DEMO-SUMMARY.md и REVIEW-FOLLOWUP.md (их опубликованные копии —
   `docs/`). Все промежуточные ошибки сохранять. Перед публикацией новой записи
   заново проверить hashes, полный decode и текст/вёрстку PDF.

Свежая установка/pytest подтверждают пользовательский код, **не** переносимость
этих OS-specific авторских утилит. Исходная PTY, commands/frames, SHA-256 cropped
images и полные выбранные source frames приложены для проверки происхождения.
