# Процесс продуктового агента

Агент среды выполняет текстовый research/strategy workflow; CLI только принимает
и валидирует результаты. Local import/metrics и строгие v3 contracts реализованы.
Реальный путь без H останавливается на запросе выбора; полный fixture lifecycle
не подтверждает человеческое решение. Live fetch и runtime reviewer API не проверены.

1. Прочитать AGENTS, status, handoff и бриф; без кейса сначала согласовать namespace/цель.
2. Размытый запрос → до трёх важных вопросов: продукт/период, определение результата, разрешённые данные/ограничения. Сохранить unknown и краткий бриф.
3. Планировать вопросы, ответы на которые способны изменить выбор; выбрать минимальные источники/лимиты и stop-condition.
4. Импортировать разрешённые MD/TXT/text-PDF/CSV/XLSX/HTML через ingest, проверить извлечение/локаторы и происхождение. Не угадывать OCR/формулы/сложные таблицы. Без разрешения на сеть не подменять fetch другим инструментом.
5. Сопоставить определения/даты/независимость, рассчитать показатели детерминированно, сохранить claims/gaps/контрсвидетельства.
   Guide/analysis выполняются по `skills/interviews.md`; роли — по
   `skills/synthetic-respondents.md`. Тема требует двух точных цитат и контрпримера.
   Учебный корпус не fieldwork; модельные роли не увеличивают число респондентов.
6. Четыре механизма: status quo, improve, refocus, close. Сильное возражение и проверка к каждому; критерии до выбора.
7. H option_choice: рекомендация не равно решение человека. Reject/revise сохраняются, молчание не approve.
   В v3 запрос pin четыре OPT разных классов + RPL с критериями/весами и selected
   recommendation в terms. Без ответа сохранить awaiting_human и checkpoint;
   не создавать live стратегию за выбранного самим агентом пользователя.
8. После выбора подготовить две согласованные стратегии, promise matrix и опровержимый эксперимент; reviewer независим только после реального отдельного контекста шага05.
9. H final_decision на proposal/digest → confirmed revision со ссылкой на approved proposal. Не переносить approval на содержательную правку.
   DEC pin первый choice APR, остальные три OPT, обе STR с ART text/manifest/hash,
   PRM matrix и EXP. Baseline unknown = null+причина, не synthetic число. Старые
   outputs восстанавливаются из pinned DEC, а не из произвольной latest STR.
10. При новых данных — адресный пересмотр по workflow review-decision, не фоновый мониторинг.

Перед каждым инструментом проверить доступы/лимит, после — результат/evidence/usage/state. При недоступности или недостатке данных допустим честный partial с минимальной следующей проверкой.
